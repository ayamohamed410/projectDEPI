## 1. Project Planning & Management

### 1.1 Project Proposal

7elhaly is an intelligent mobile application developed with Flutter that bridges the gap between homeowners and skilled independent craftsmen. Utilizing Google's Gemini AI, the platform enables users to submit problem descriptions in plain written text (including local Arabic dialects). Gemini AI parses these inputs, categorizes the required service, estimates repair scope and costs, and directly matches the user with qualified local craftsmen.

**Core Objectives:**

- **AI-Driven Service Categorization:** Implement natural language processing (NLP) to convert unstructured text input into structured repair categories.
- **Direct Craftsman Matching:** Connect homeowners directly with verified individual service providers based on location, rating, and specialization.
- **Upfront Cost Estimation:** Provide transparent cost ranges and time estimates generated by AI before booking confirmation.
- **Scalable Architecture:** Maintain high application performance and responsiveness using Flutter Clean Architecture and BLoC state management.

**Project Scope Definition:**

- **In-Scope:** Text-based prompt analysis, Gemini API integration via Dio, direct craftsman search/booking, Firebase Authentication, FCM push notifications, interactive Google Maps, and Hive local storage.
- **Out-of-Scope:** Physical payment gateway integrations (cash-on-delivery approach used), web-based administrative consoles, and automated hardware IoT diagnostics.

### 1.4 Risk Assessment & Mitigation Plan

| Risk Description | Severity | Mitigation Strategy |
|---|---|---|
| Inconsistent JSON formatting from AI API | High | Implement strict JSON schema enforcement in system prompts and fallback parser mechanisms. |
| Slow response times from AI endpoints | Medium | Use animated shimmer skeletons during API calls and cache frequent query categories locally in Hive. |
| Low craftsman density in specific locations | Medium | Fallback to nearest available category specialist with expanded search radiuses. |
| Network loss during active booking | Low | Persist incomplete bookings locally in Hive DB and sync automatically when internet restores. |

### 1.5 Key Performance Indicators (KPIs)

- **AI Parsing Precision:** Accuracy of AI service categorization from user text prompts exceeding 90%.
- **System Responsiveness:** Average response time for Gemini API processing under 2.5 seconds.
- **UI Performance:** App UI frame rate maintained at 60 FPS across mid-range Android/iOS devices.
- **System Stability:** Zero critical unhandled exceptions across primary user booking flows.

## 2. Literature Review & Project Rationale

### 2.1 Project Rationale & Design Philosophy

Traditional service directories often require users to navigate rigid, multi-layered manually categorized menus. 7elhaly innovates upon this model by introducing an AI-first approach: users describe their problem in natural text, and the system automatically determines the exact trade category, urgency level, and estimated cost range, streamlining the journey directly to qualified local craftsmen.

### 2.2 Core Architectural Strengths

- **Advanced Arabic NLP:** Tailored prompt engineering to accurately parse Arabic dialects (Egyptian slang) and extract structured repair summaries, severity levels, and required toolkits.
- **Streamlined User Journey:** A friction-free user flow allowing homeowners to submit a single text prompt and receive curated craftsman options in seconds.
- **Local Offline Caching:** Integration of Hive NoSQL for instant offline caching of search history, active bookings, and favorite craftsman profiles.

## 3. Requirements Gathering & Software Engineering Specifications

### 3.1 Stakeholder Analysis

- **Homeowners / Clients:** Seek instant, reliable problem diagnosis from written text without navigating complex manual categories.
- **Independent Craftsmen:** Receive direct service requests tailored to their specific technical skills and geographical location.
- **Project Evaluators:** Assess technical rigor, software design patterns, and code maintainability.

### 3.2 Functional Requirements (FRs)

| Req ID | Module Name | Functional Description |
|---|---|---|
| FR-01 | User Authentication | Secure user sign-up, login, and profile management via Firebase Auth. |
| FR-02 | Text-based AI Analysis | Process written issue descriptions using Gemini API to output structured JSON containing category, severity, and estimated cost. |
| FR-03 | Craftsman Matching Engine | Query Firestore for craftsmen matching the AI-determined category, sorted by distance and rating. |
| FR-04 | Direct Booking & Tracking | Allow clients to book individual craftsmen, select appointment slots, and view status updates. |
| FR-05 | Push Notifications | Trigger real-time FCM notifications for booking updates, acceptances, and reminders. |
| FR-06 | Offline Data Sync | Cache recent searches, active bookings, and profile data locally using Hive DB. |

### 3.3 Non-Functional Requirements (NFRs)

- **Performance:** API network calls handled asynchronously with Dio, ensuring main UI thread remains unblocked.
- **Security:** All network communications executed over HTTPS with secure Firebase security rules for database access.
- **Usability:** Clean UI following Google's Material Design 3 guidelines with light/dark theme support.
- **Maintainability:** Loose coupling achieved using Clean Architecture (Domain, Data, and Presentation layers).
